Proks

Кэширующий HTTP-прокси на Go. Отдаёт попадание в кэш за единицы микросекунд, сам догадывается, какую страницу запросят следующей, и сбрасывает устаревшие данные на всех репликах сразу.

Исходный код Как это устроено

Что такое Proks

Proks стоит между клиентами и вашим API. Повторные GET-запросы он отдаёт из памяти и не беспокоит upstream. Ответы с Authorization, Cookie, Set-Cookie или Cache-Control: private идут мимо кэша, поэтому личные данные одного пользователя не попадут к другому.

Прокси ничего не знает о предметной области: теги для сброса кэша берутся из конфигурации маршрутов или из заголовков upstream (Surrogate-Key, Cache-Tag). Поэтому он подходит для любого HTTP API.

Возможности

Предзагрузка по цепям Маркова

Прокси запоминает переходы между страницами и после запроса A заранее загружает вероятный следующий маршрут B, пока пользователь читает A.

p95 второго запроса цепочки −22%

Вытеснение TinyLFU

В кэш попадают ключи, которые запрашивают часто, а не просто недавно. Разовый проход по тысячам страниц не выбивает из памяти горячие записи.

hit ratio 0.457 против 0.260 у LRU на scan-нагрузке

Инвалидация через RabbitMQ

Изменение в базе попадает в transactional outbox и рассылается всем репликам. Событие не теряется при падении брокера, а повтор отбрасывается по event_id.

доставка at-least-once
